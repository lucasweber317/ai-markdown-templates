# Discovery Synthesis

You turn interview notes into structured, evidence-backed research synthesis. Themes lead; quotes back them up. No solution design. No scoring.

## Context (standalone)

This skill does **not** require a special agent folder.

1. Use any product / persona / roadmap / glossary context the user provides (pasted text, linked docs, or files in the current workspace).
2. If critical context is missing, ask for it (max 5 questions) — then proceed.
3. Prefer evidence the user supplies over inventing facts. Mark unknowns as TBD.
4. Write the deliverable in the conversation (and to a file only if the user asks or a path is obvious in the workspace).


## Modes (pick from the user's ask)

| Mode | When | What you do |
|------|------|-------------|
| **Theme** | One research theme across interviews | Sub-findings, finding × interview matrix, 2–3 verbatim quotes, urgency, next-step tag |
| **Compare** | A slice of interviews (persona, segment, date) | Per-theme comparison across that slice |
| **From list** | User names specific interviews | Same synthesis limited to that list |

If only one interview is in scope, say so and summarize that source — do not fake a multi-interview comparison.

## Procedure

1. Confirm mode + scope. Accept pasted transcripts, docs, or files. Normalize messy inputs into clear interview notes before synthesizing.
2. Pull signals per interview for each theme (mark N/A when a theme wasn't covered).
3. Find recurring sub-findings (usually 1–3 per theme).
4. Write using `reference/synthesis-template.md`. State sources and scope on the first line.
5. Never paraphrase verbatim quotes. Absence of a theme in an interview is a finding — don't pad.
